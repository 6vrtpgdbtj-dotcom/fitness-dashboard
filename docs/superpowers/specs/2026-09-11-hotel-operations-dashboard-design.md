# 호텔형 PT 운영 대시보드 최종 보정 설계

## 목표

1986 FITNESS 중산점 관리자가 형식이 다른 Google Sheets를 연결하면 PT 팀 매출, FC 매출, 트레이너별 신규·재등록 매출, 수업 및 회원 현황을 한국시간 기준으로 한눈에 확인한다. 트레이너를 나중에 추가해도 이름 또는 이메일이 시트의 담당자 값과 일치하면 기존 기록과 새 기록이 자동으로 그 트레이너에게 연결되어야 한다.

## 확정한 제품 원칙

- PT 팀 매출을 화면의 가장 중요한 수치로 둔다.
- FC 매출, 등록, 수업, 재등록 확인 회원은 보조 지표로 배치한다.
- 유효한 매출 행은 담당자 미지정, 퇴사자, 아직 등록하지 않은 트레이너의 행이어도 팀 합계에서 빠지지 않는다.
- 개인 실적은 시트 구조에서 담당자가 확정되고 활성 트레이너와 이름 또는 이메일이 정확히 일치한 행만 포함한다.
- 시트 원본은 읽기 전용이며 앱에서 원본 값을 임의로 바꾸지 않는다.
- 조회 기간과 모든 날짜·시간 판정은 `Asia/Seoul` 기준을 사용한다.

## 데이터 집계 및 자동 연결

### 계층형 담당자 블록 해석

매출시트에서 `정윤수`처럼 트레이너 이름이 상위 제목, 병합 셀 또는 열 블록의 머리글로 나오면 다음 트레이너 제목이 시작되기 전까지 그 블록의 매출 행에 담당자를 상속한다. 하위 행이나 보조 머리글에 `담당자 배정`, `구분`, `회원명` 같은 안내 문구가 있어도 상위 트레이너 컨텍스트를 지우지 않는다. 즉 `정윤수` 아래의 `담당자 배정` 영역에 있는 매출은 정윤수 실적으로 잡는다.

파서는 직접 입력된 담당자 셀을 1순위, 같은 열/블록의 상위 트레이너 제목을 2순위로 사용한다. 새 트레이너 제목, 빈 구획을 동반한 명확한 섹션 경계, 또는 다른 매출 블록이 시작되면 상속을 종료한다. 서로 충돌하는 두 이름이 동시에 후보가 되면 개인에게 임의 배정하지 않고 팀 합계만 유지한다.

### 팀 합계와 개인 합계의 분리

`valid`인 PT·FC 등록 행은 담당 트레이너 연결 여부와 무관하게 팀 합계에 포함한다. 담당자 값이 비어 있거나 현재 활성 트레이너와 일치하지 않아도 매출 기록 자체를 `review_required`로 낮추지 않는다. 대신 `trainer_id`를 비워 두어 개인 실적과 트레이너 권한 범위에서는 제외한다.

담당자 힌트가 활성 트레이너의 표시 이름 또는 이메일과 정확히 한 명에게 일치하면 `trainer_id`를 연결한다. 중복 이름처럼 여러 명에게 일치하는 경우 개인에게 연결하지 않되 팀 합계는 유지한다.

### 새 트레이너 추가

관리자가 트레이너를 이름·이메일로 추가하거나 비활성 트레이너를 다시 활성화하면 해당 조직의 저장된 시트 힌트를 재처리한다. 따라서 추가 전에 들어온 과거 매출·회원·수업도 다시 매칭된다. 이후 동기화되는 행에는 동일 규칙이 즉시 적용된다. 트레이너가 Google 시트를 직접 연결하거나 별도 승인할 필요는 없다.

담당자 미지정·불일치 행은 팀 수치에서 숨기지 않는다. 관리자 화면에서 `담당 미지정`으로 식별하고, 향후 이름 또는 이메일이 맞는 트레이너를 추가하면 자동 해소한다. 연결되지 않은 행은 트레이너 개인에게 노출하지 않는다.

## 수업 현황

- 오늘 수업은 `starts_at` 오름차순으로 표시하고 시간 미정 행은 마지막에 둔다.
- 기간별 수업 표는 날짜를 최신순으로 묶되 같은 날짜 안에서는 시작 시간을 이른 순서대로 표시한다.
- 각 행은 시간, 회원명, 담당 트레이너, 완료/예정 상태를 함께 보여 준다.
- 당일 이미 지난 수업은 완료로 판정하며, `30/40` 표기는 총 40회 중 30회차로 해석한다.
- 회원 연결이 아직 되지 않았더라도 스케줄 시트의 원문 회원명은 표시한다.

## 화면 구성

상단에는 지점명, 한국시간 기준 조회 기간, 마지막 동기화 시각과 연결 상태를 둔다. 첫 데이터 영역은 넓은 PT 팀 매출 모듈이며, FC 매출과 신규·재등록 총액은 좁은 보조 열로 둔다. 그 아래에는 매출 추이, 오늘 수업, 재등록 확인 회원, 트레이너별 실적을 배치한다.

트레이너별 실적은 개인별 총매출 안에서 신규·재등록과 실제 시트의 유입 경로(필드, OT, 상담, 워크인 등)를 나눈다. 원본에 없는 구분값을 만들어내지 않고 새 값은 동적 분류로 추가한다.

### 호텔형 시각 언어

- 바탕은 따뜻한 아이보리, 핵심 운영 레일은 깊은 차콜, 강조는 절제된 브론즈를 사용한다.
- 장식용 카드 반복을 줄이고 넓은 매출 무대와 세로 운영 레일이 대비되는 비대칭 구성을 쓴다.
- Pretendard Variable로 한국어 본문을 읽기 쉽게 유지하고 Archivo는 숫자와 짧은 영문 라벨에만 사용한다.
- 반경은 4–8px, 테두리는 낮은 대비의 1px, 그림자는 중요한 떠 있는 상태에만 사용한다.

`PT Revenue Ledger`는 팀 PT 총액, 전월/기간 변화, 신규·재등록 분해, 트레이너별 기여를 한 화면에서 연결하는 핵심 모듈이다. 선택한 트레이너나 기간이 바뀌면 관련 수치와 차트가 함께 강조되어 합계와 근거를 바로 비교할 수 있다.

## 모션과 모바일

첫 진입은 팀 매출 수치가 먼저 정착하고 신규·재등록 막대와 트레이너 행이 이어서 나타나는 순서형 모션을 사용한다. 기간·트레이너 선택은 160–260ms 안에서 관련 수치와 강조 상태를 갱신한다. 버튼, 표 행, 차트 선택에 호버·키보드 포커스·선택 피드백을 제공하고 `prefers-reduced-motion`에서는 최종 상태를 즉시 표시한다.

390px에서는 PT 팀 매출, 오늘 수업, 재등록 확인 회원, 개인 실적, 추이 순으로 재배치한다. 보조 지표는 두 열 요약으로 축약하고 넓은 표는 핵심 열을 카드형 행으로 변환한다. 문서 자체에는 가로 스크롤이 생기지 않으며 필요한 차트 내부만 제한적으로 스크롤한다.

## 오류·빈 상태

- 일부 시트 실패 시 성공한 시트의 수치와 마지막 성공 시각을 유지하고 실패한 연결만 표시한다.
- 데이터가 실제로 0인 상태와 연결·매핑 미확인 상태를 다른 문구로 표시한다.
- 새 트레이너가 아직 매칭할 기록이 없으면 0원으로 표시하되 오류로 보이지 않게 한다.
- 중복 이름 또는 충돌한 담당자 힌트는 개인 실적에서 제외하고 관리자 확인 대상으로 식별한다.

## 구현 범위

- 계층형 상위 트레이너 제목과 열/블록 범위를 해석하는 매출 파서를 보정한다.
- Supabase 담당자 자동 배정 함수를 보정하고 신규/활성화 시 저장된 레코드를 재처리한다.
- 팀 합계와 개인 합계가 분리되는 데이터베이스 회귀 테스트를 추가한다.
- 오늘 수업 및 수업 상세 정렬을 하나의 한국시간 정렬 규칙으로 통일하고 단위 테스트를 추가한다.
- 대시보드와 상세 화면을 호텔형 토큰·구성으로 변경한다.
- 390px 모바일, 빈 상태, 부분 실패, 일반 상태, 모션 감소 상태를 브라우저로 검증한다.
- 전체 테스트, 린트, 타입 검사, 프로덕션 빌드 후 Supabase 마이그레이션과 Vercel 배포를 수행한다.

## 완료 기준

1. `정윤수` 상위 제목 아래 `담당자 배정` 영역의 매출이 정윤수 개인 실적에 포함된다.
2. 담당자 없는 FC 및 과거·미등록 트레이너의 PT 매출이 팀 합계에서 사라지지 않는다.
3. 활성 트레이너 개인 실적에는 시트 구조상 확정되고 정확히 매칭된 행만 포함된다.
4. 새 트레이너를 추가하면 별도 시트 작업 없이 과거와 이후 기록이 자동 연결된다.
5. 수업이 한국시간의 시간대 순서로 나오며 원문 회원명이 보존된다.
6. 데스크톱 첫 화면에서 PT 팀 매출이 가장 강하게 보이고 390px에서 겹침·문서 가로 스크롤이 없다.
7. 정상·0·미확인·부분 실패 상태가 구분되고 전체 자동화 검증이 통과한다.
