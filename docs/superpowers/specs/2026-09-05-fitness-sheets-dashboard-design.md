# 1986 FITNESS Google Sheets 통합 대시보드 설계

## 목적

1986 FITNESS 중산점이 여러 트레이너의 기존 Google Sheets를 관리자 계정으로 한 번 연결하고, 서로 다른 시트 구조를 자동 변환해 회원·등록·상담·수업 현황을 통합 조회하는 배포형 웹서비스를 만든다. 트레이너는 기존 시트만 계속 사용하며 별도 연동 작업을 하지 않는다.

## 사용자와 권한

### 관리자

- Google 계정으로 로그인한다.
- Google Sheets를 개수 제한 없이 추가하거나 연결 해제한다.
- 전체 회원, 등록, 매출, 상담, 수업 데이터를 조회한다.
- 트레이너 계정과 이메일을 등록하고 데이터 접근 범위를 지정한다.
- 자동 매핑 결과, 중복 후보, 누락 필드와 동기화 오류를 확인한다.
- 연결 해제 시 과거 데이터 보존 또는 삭제를 선택한다.

### 트레이너

- 관리자가 등록한 Google 계정으로 로그인한다.
- 본인이 담당하는 회원과 본인 실적만 조회한다.
- Google Sheets 연결이나 컬럼 매핑을 수행하지 않는다.
- 원본 시트는 기존 방식대로 사용한다.

## 기술 구성

- 프런트엔드와 API: Next.js, TypeScript
- 인증과 데이터베이스: Supabase Auth, PostgreSQL, Row Level Security
- 실시간 화면 갱신: Supabase Realtime
- 원본 연동: Google OAuth, Google Sheets API, Google Drive API
- 배포: Vercel
- 브라우저 검증: Playwright

배포 환경과 데이터베이스는 한국 사용자에게 지연이 적은 가까운 리전을 사용한다.

## Google 연결

관리자가 사이트에서 Google 로그인을 승인하고 Google 파일 선택기 또는 시트 URL로 원본 시트를 등록한다. 승인 토큰은 서버에서만 암호화해 보관하며 브라우저나 트레이너 계정에 노출하지 않는다.

각 연결에는 다음 정보를 저장한다.

- Google Spreadsheet ID
- 표시 이름과 지점
- 연결한 관리자
- 담당 트레이너 또는 트레이너 식별 컬럼
- 탐지된 탭과 헤더
- 현재 매핑 버전
- 마지막 정상 동기화 시간
- 변경 알림 채널과 만료 시각
- 연결 상태와 최근 오류

Google Drive 변경 알림은 변경 사실만 전달하므로, 알림 수신 후 해당 시트를 Sheets API로 다시 읽는다. 변경 채널은 만료 전에 자동 갱신한다. 알림 누락이나 일시적 장애에 대비해 정기 전체 검증 동기화도 실행한다.

## 데이터 처리 흐름

1. 관리자가 Google Sheet를 연결한다.
2. 서버가 탭 이름, 헤더, 데이터 샘플과 값 유형을 읽는다.
3. 원본 데이터를 변경하지 않고 스냅샷으로 저장한다.
4. 헤더명, 동의어, 값 유형과 과거 매핑을 이용해 표준 컬럼을 찾는다.
5. 회원, 등록, 상담, 수업 데이터로 정규화한다.
6. 검증을 통과한 행을 현재 데이터와 이력 데이터에 반영한다.
7. 변경된 집계 결과를 Realtime으로 접속 중인 대시보드에 전달한다.
8. 동기화 실행 결과와 변경 내역을 감사 로그에 기록한다.

## 구조 변경 대응

시트별 고정 열 번호를 사용하지 않는다. 다음 순서로 컬럼을 판별한다.

1. 관리자가 확정한 최근 매핑
2. 정규화한 헤더명 완전 일치
3. 사전에 정의한 동의어 사전
4. 날짜, 금액, 세션, 상태 등 값 유형과 분포
5. 유사도 기반 자동 추천

띄어쓰기, 특수문자, 대소문자, 열 순서 변경, 새 열 추가와 알려진 동의어 변경은 자동 처리한다. 인식하지 못한 선택 필드는 비워 두고 다른 데이터는 계속 반영한다. 필수 식별 정보가 없는 행은 정상 집계에서 제외하고 확인 목록에 보관한다. 한 시트의 실패는 다른 연결의 동기화를 막지 않는다.

관리자가 매핑을 수정하면 새 버전을 저장한다. 이후 같은 헤더 구조에는 해당 매핑을 우선 적용한다. 모든 원본 스냅샷과 매핑 버전을 보관해 잘못된 자동 인식 결과를 재처리할 수 있게 한다.

## 중복과 이력

- 원본 연결 ID, 탭 ID와 행 지문을 조합해 반복 동기화의 중복 삽입을 방지한다.
- 계약ID, 리드ID, 수업ID와 회원ID가 있으면 우선 식별자로 사용한다.
- 회원ID가 없으면 이름, 생년월일, 연락처 끝 4자리와 담당 트레이너를 이용해 중복 후보 점수를 계산한다.
- 확실한 일치만 자동 연결하고 애매한 항목은 관리자 병합 목록에 표시한다.
- 원본에서 행이 이동하거나 정렬돼도 동일한 레코드로 추적한다.
- 원본 행이 삭제되거나 수정돼도 이전 정상 스냅샷과 매출 이력은 감사 목적으로 보존한다.

## 표준 데이터 영역

### 회원

회원ID, 이름, 성별, 생년월일, 나이, 연령대, 담당 트레이너, 운동 목적, 최초 유입경로, 최초 상담일, 최초 등록일, 현재 상태, 잔여 세션, 누적 등록 세션, 누적 결제금액, 최근 등록일, 종료 예정일, 소개자, 비고를 관리한다.

### 등록

계약ID, 회원ID, 등록일, 등록구분, 유입경로, 상품, 등록 세션, 정상금액, 실결제금액, 회당단가, 할인금액, 결제방법, 계약 담당자, 수업 담당자, 종료 예정일과 상태를 이력으로 관리한다. 기존 행을 덮어쓰지 않는다.

### 상담

리드ID, 최초 접점일, 상담일, 담당 트레이너, 유입경로, 운동 목적, 상담 상태, 등록 여부, 등록일, 회원ID, 등록 세션, 등록금액과 미등록 사유를 관리한다.

### 수업

수업ID, 수업일, 회원ID, 담당 트레이너, 차감 세션, 잔여 세션과 수업 상태를 이력으로 관리한다.

## 화면 구성

### 공통

- Google 로그인
- 계정 메뉴와 로그아웃
- 적용 중인 기간과 담당 범위 표시
- 마지막 데이터 갱신 시각과 동기화 상태
- 데스크톱 사이드바와 모바일 하단 메뉴

### 관리자

- 통합 현황: 전체 매출, 신규·재등록, 신규등록률, 수업 수와 기간별 추이
- 트레이너 비교: 매출, 신규등록, 재등록, 상담 전환율과 수업 생산성
- 회원 관리: 상태, 잔여 세션, 종료 예정일, 휴면 위험과 재등록 후보
- 등록·매출: 계약 이력, 등록구분, 상품, 할인과 결제수단
- 상담 리드: 유입경로별 리드, 상담, 등록, 등록률, 신규매출과 평균값
- 수업 현황: 월별 수업 수, 출석, 취소, 노쇼와 세션 소진 속도
- 시트 연결: 추가, 해제, 담당자 지정, 탭·컬럼 매핑과 동기화 상태
- 데이터 점검: 누락, 중복 후보, 미확정 매핑과 처리 이력
- 사용자 관리: 관리자와 트레이너 초대, 활성화, 접근 범위 설정

### 트레이너

- 개인 현황: 본인 매출, 목표 달성률, 신규·재등록과 상담 전환율
- 담당 회원: 상태, 잔여 세션, 최근 수업과 종료 예정일
- 수업 현황: 오늘 일정, 이번 달 수업 수, 취소와 노쇼
- 재등록 관리: 예상 소진일과 연락 권장 회원
- 개인 상담: 유입경로와 상담 결과

## 디자인 시스템

운영 대시보드는 어두운 차콜과 웜 블랙을 기본으로 하고 라임 계열을 연결 정상, 선택 상태와 핵심 그래프에 제한적으로 사용한다. 큰 배너보다 데이터 표와 그래프가 먼저 보이는 밀도 높은 레이아웃을 사용한다.

- 한글 본문: Pretendard Variable
- 영문, 브랜드명과 주요 숫자: Archivo
- 제목은 굵기보다 크기와 여백으로 계층을 구분한다.
- 카드 모서리는 절제된 중간 반경을 사용한다.
- 표는 세로선을 제거하고 행 구분선과 상태 색상만 사용한다.
- 숫자는 탭형 숫자를 적용해 비교가 쉽도록 한다.
- 모바일에서는 핵심 지표, 오늘 수업과 재등록 대상을 먼저 배치한다.
- 로딩은 스켈레톤, 동기화는 작은 상태 표시와 갱신 시각으로 표현한다.
- 과도한 그라데이션, 네온 효과, 장식용 아이콘과 템플릿형 카드 남발을 피한다.

## 오류와 복구

- 시트 연결 실패: 원인을 표시하고 기존 정상 데이터를 유지한다.
- 토큰 만료 또는 권한 취소: 관리자에게 재연결을 요청하며 다른 시트는 계속 처리한다.
- API 제한: 지수 백오프로 재시도하고 중복 작업을 합친다.
- 변경 알림 누락: 정기 전체 검증으로 복구한다.
- 컬럼 변경: 자동 재분석 후 확신도 낮은 필드만 확인 목록에 추가한다.
- 값 형식 오류: 해당 필드를 제외하고 원본값과 오류 사유를 보존한다.
- 중복 이벤트: 동기화 실행 키와 행 지문으로 멱등 처리한다.
- 대량 변경: 작업을 시트와 탭 단위로 나눠 처리하고 진행 상태를 기록한다.

## 보안과 개인정보

- 원본 Google 토큰과 서버 전용 키를 클라이언트 번들에 포함하지 않는다.
- 모든 데이터 테이블에 지점과 사용자 범위를 포함한다.
- Supabase Row Level Security로 관리자와 트레이너의 조회 범위를 강제한다.
- API에서도 동일한 소유권과 역할 검사를 수행한다.
- 전체 연락처는 기본 수집 대상에서 제외하고 필요한 경우 끝 4자리만 저장한다.
- 분석 API는 가능한 한 집계 결과만 반환한다.
- 민감 정보와 토큰은 로그에 기록하지 않는다.
- 시트 연결, 권한 변경, 수동 병합과 데이터 삭제를 감사 로그에 남긴다.

## 테스트와 완료 기준

- 시트를 3개 이상 연결하고 추가 연결이 가능한지 확인한다.
- 서로 다른 탭명과 헤더명을 표준 구조로 변환하는 단위 테스트를 작성한다.
- 열 이동, 열 추가, 알려진 이름 변경 후에도 동기화되는지 확인한다.
- 필수 필드 누락 시 다른 정상 데이터가 계속 반영되는지 확인한다.
- 같은 원본을 반복 처리해도 회원과 매출이 중복되지 않는지 확인한다.
- 삭제, 정렬과 행 이동 후 이력이 유지되는지 확인한다.
- 관리자와 트레이너의 데이터 접근 범위를 RLS와 API 통합 테스트로 검증한다.
- 변경 알림 수신, 채널 갱신, 실패 재시도와 정기 복구를 검증한다.
- 주요 관리자·트레이너 흐름을 Playwright로 데스크톱과 모바일에서 검증한다.
- 인증되지 않은 사용자의 페이지와 API 접근이 차단되는지 확인한다.
- 동기화 실패 상태에서도 이전 정상 대시보드가 표시되는지 확인한다.
- 배포 환경에서 Google 콜백 URL, 변경 알림 URL과 환경 변수를 점검한다.

## 1차 버전에서 제외

- 대시보드에서 Google Sheets 원본 직접 수정
- 급여·수당 자동 정산
- 문자나 카카오톡 자동 발송
- 결제 단말기 연동
- AI 기반 운동 처방
- 여러 지점을 묶는 본사 멀티테넌트 기능

이 항목들은 핵심 동기화와 대시보드가 안정화된 후 별도 단계로 추가한다.

## 외부 제약 참고

- Google Drive 변경 알림은 변경 사실만 전달하며 실제 데이터를 포함하지 않으므로 알림 후 Sheets API 조회가 필요하다: https://developers.google.com/workspace/drive/api/guides/push
- Vercel 예약 작업은 HTTP 함수 호출 방식이며 실패 자동 재시도가 없으므로 애플리케이션에서 재시도와 실행 기록을 관리한다: https://vercel.com/docs/cron-jobs/manage-cron-jobs
- 화면 실시간 갱신은 인증된 Supabase Realtime 채널과 RLS를 사용한다: https://supabase.com/docs/guides/realtime/subscribing-to-database-changes
